# Mock catalog fixtures

These fixtures power `pnpm dev:mock`. Catalog identities use real producers and
products. They are a small, fixed catalog for browsing, search, ownership,
regional filters, bottle details, and release families. Existing IDs stay stable
because tastings, collections, flights, and other fixtures link to them.

Catalog facts were checked on **2026-09-02**. Sources below explain the factual
choices; the TypeScript fixtures and API contracts define their representation.
Descriptions are short summaries, not copied marketing text.

User accounts, activity, scores, tasting counts, prices, reviews, events, and
catalog totals are synthetic UI samples, not observations about real people or
current production data. The database test builders in `lib/test/fixtures.ts`
and the CLI's database seed command are separate from this in-memory catalog.

## Activity examples

`activity.ts` includes tasting sessions, member reviews, and single and grouped
library additions. The activity page combines these with the critic reviews in
`externalReviews.ts`. The shared component stories use the same examples and
also cover a critic review without a reviewer byline. Library status stays in
the library data but is not shown in activity rows.

## Adding catalog data

- Give each producer its own kind, country, region, address, and ownership.
  Start from neutral defaults, never another producer.
- Set a Bottle's brand and distillers separately. Owning a distillery does not
  make a company the brand or distiller of every bottle it owns.
- Use the marketed product name. Keep exact age, ABV, and release year in their
  fields. Never transfer one batch's traits to another batch.
- Add a source for new facts here. Leave unverified facts null, including map
  coordinates, dates, complete blend recipes, and image permissions.
- Keep source links on historical events. Link an acquisition to the owner that
  actually existed at that date.
- Run `pnpm --filter @peated/server test -- src/orpc/mock/router.test.ts src/orpc/mock/app.test.ts`.
