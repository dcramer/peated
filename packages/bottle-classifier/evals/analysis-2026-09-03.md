# Initial classifier accuracy analysis, 2026-09-03

This document records the failures and proposed work before the experiments.
The dated
[research summary](../../../docs/research/bottle-classifier-evaluation-2026-09.md)
records what was tested, what was kept, and the current 105-case baseline.

The first Luna experiment should clarify how evidence establishes a marketed
release. More reasoning effort alone did not remove the repeated unsafe matches.
The [baseline](./README.md) records the results before any behavior or scoring
changes. Findings below come from the web-enabled Luna high run and its targeted
repeats unless noted otherwise. Proposed changes are hypotheses, not measured
improvements.

Success means more evidence-supported exact Bottle decisions and complete
creation drafts, with fewer incorrect existing matches and no observed increase
in unsupported audit edits. Keep the current two-query and eight-turn budgets
for the first experiment; measure latency, token cost, and `no_match`/review load
against an unchanged Luna high run. No new production side effects are
needed. Retain the single-agent architecture: these traces implicate evidence
interpretation, input context, and rule consistency, not a missing agent role.

## What the score measures

Luna high passed 73/102 cases. Its 29 failures fall into these diagnostic groups:

| Failure group                                  | Cases | Interpretation                                                 |
| ---------------------------------------------- | ----: | -------------------------------------------------------------- |
| Incorrect existing matches                     |     3 | Wrong action or Bottle ID; highest priority                    |
| Other identity decisions or `no_match` results |     8 | Includes two policy/test case conflicts                        |
| Created Bottle fields or names                 |    12 | Includes possible expectation problems and missing evidence    |
| Audits                                         |     6 | Includes one turn-limit error and strict operation comparisons |

This is a check of the complete result, not a clean identity-accuracy percentage.
Do not combine corrected scoring rules and a prompt change into one claimed gain.

The production path is the
[server wrapper](../../../apps/server/src/agents/bottleClassifier/service.ts),
the [package code](../src/classifierRuntime.ts),
[agent input](../src/runtime/agentInput.ts),
[prompt](../src/instructions.ts), tools, and
[final validation](../src/reviewPolicy.ts). The server owns storage and
[automation approval](../../../apps/server/src/lib/priceMatchingProposals.ts).
Evals exercise the real package code with test catalog data; they do
not prove production retrieval or persistence behavior. A wrong classifier
match is not by itself evidence of an automatic production write.

Before the model runs, normalization, image extraction, local retrieval, and
verified identity anchors supply context. The model explores bounded read-only
tools and returns the structured [decision contract](../src/contract.ts).
Post-model code normalizes the draft, validates references and entity IDs,
rejects unsafe states, and derives automation eligibility. Diagnosis must compare
the evidence, model decision, and final result at those boundaries.

## 1. Establish the meaning of extra identity details

Two failures show the same problem: the model treats an empty structured cask
field as permission to ignore a specific cask in the candidate's name.

- The [Elijah Craig case](../src/eval-fixtures/decision-cases/new_bottles/store-listing-creates-elijah-craig-18-single-barrel-when-local-candidate-is-barrel-specific.json)
  has a general 18-year-old Single Barrel source and candidate 16142 named
  `Single Barrel 18-year-old (No. 4040)`. Its structured cask and edition fields
  are empty. Luna matched that candidate in all three attempts.
- The [Masterson's case](../src/eval-fixtures/decision-cases/new_bottles/store-listing-creates-mastersons-french-oak-finish-instead-of-matching-plain-rye-or-barrel-specific-bottle.json)
  has a French Oak Finish source and candidate 16442 with `Barrel F2-038` in its
  name. The matched candidate is a barrel-specific French Oak Finish, despite
  the test case title's shorthand about a plain rye sibling. Luna acknowledged
  that the source did not verify the barrel, yet matched it in all three attempts.

The prompt already says an unsupported extra marketed trait makes a candidate
too specific. However, its compatibility step emphasizes populated fields and
allows missing fields. The experiment should make this distinction explicit:
**a null structured field does not erase identity evidence in a name**. Compare
supported marketed traits on both sides before selecting a candidate. If a
candidate's extra code matters, establish whether it identifies a marketed
release or is merely an observation. Leave unresolved compatibility unresolved.

The opposite error occurs in the
[High Country case](../src/eval-fixtures/decision-cases/match_existing/image-backed-photo-matches-high-west-high-country-batch-23j12.json).
All three models selected batch candidate 44284 instead of ongoing-release
candidate 12825. Luna accepted extracted `edition: Batch No. 23J12` as marketed
identity and made no observed tool calls. The test case identifies it as an
ordinary lot code. Extraction reports visible facts; it should not silently
settle their role in Bottle identity. Ask for evidence of that role when it
changes the match, using the existing bounded source tools.

[Experiment 01](./experiments/01-release-identity.md) tested and rejected a
general prompt change to that decision step. It did not fix the target cases and
introduced regressions. Do not extend that wording with brand rules or code
patterns. The next identity experiment should separate supported source identity
from candidate choice, then measure the extra model cost and time.

## 2. Reuse retrieved entities accurately

In the [Mars Komagatake creation](../src/eval-fixtures/decision-cases/new_bottles/image-backed-photo-creates-mars-komagatake-2022-edition.json),
the final draft proposed a new Mars Shinshu Distillery instead of existing Entity 1953. That Entity was already in initial results and a `search_entities` response,
with a relevant reference alias. More search alone does not address this failure.

Inspect the model decision before entity sanitization first: the current saved eval
result contains the final draft, and
[entity validation](../src/reviewPolicy.ts) can remove an ID when the accompanying
name is inconsistent. Then test clearer existing-entity and alias context before
creating a new Entity. Entity kind does not by itself prohibit using the Entity
in a Bottle relationship.

There is also a concrete input-description mismatch: the prompt says
`retrievedFor` identifies the source field, but initial retrieval stores the
query, not its field role. Correct that description or preserve the actual role
through retrieval. Test shared roles and similar names as comparison cases; never select
an ID from approximate name matching alone.

## 3. Make audit evidence rules consistent

The [one-image audit](../src/eval-fixtures/audit-cases/image-only-extraction-does-not-overwrite-populated-fields.json)
exceeded eight turns. Its error trace includes rejected attempts to change
populated `bottlingYear` and `maturation` without qualifying evidence. A useful
experiment is to make rejection recovery explicit: obtain the missing evidence
if available, remove unsupported fields, or finish without that change. Do not
repeat a rejected proposal without new evidence. Raising the turn limit would
not fix the underlying evidence problem.

Separately, the prompt permits a stored name or edition correction from one
readable label plus a matching producer title. The
[patch guard](../src/runtime/bottlePatchEvidence.ts) includes `name` and `edition`
in fields requiring a matching structured observation or two agreeing label
images when populated. The
[proposal tool](../src/tools/proposeOperations.ts) enforces that guard. Align the
instructions with the enforced rule before asking the model to follow the
exception. Any intentional exception needs its own evidence design and focused
guard tests; it must not emerge from a model workaround.

## 4. Review expectations before tuning field completeness

These are review candidates, not justification to loosen the suite automatically:

- **Cold Brew (resolved in M02):** producer evidence establishes that Jameson
  Cold Brew combines whiskey with coffee and is bottled at 30% ABV. Both cases
  now expect `no_match` under the additive-flavor rule. A separate Ardbeg case
  covers current-assignment behavior. The [M02 record](./experiments/M02-policy-conflicts.md)
  reports the historical score correction.
- **Categories and names (resolved in M03):** producer evidence establishes that
  Black Label Islay Origin is a blended malt and Hedonism² is a blended grain.
  Stable-name evidence also removes `Whisky` from Maker's Mark while preserving
  the shorter Creag Isle Bottle name. The
  [M03 record](./experiments/M03-names-and-categories.md) reports the test case
  corrections and focused Luna high checks.
- **Changing source pages (resolved in M05):** the Springbank 25 source page returned a specific
  2023 release, while the test case expected the ongoing-release candidate. A live
  page and an older expectation can describe different inputs. Preserve reviewed
  source evidence for controlled experiments and report live-page behavior
  separately. The [M05 record](./experiments/M05-fixed-evidence.md) adds this
  controlled lane and documents its first live comparison.
- **Audit extras (resolved in M04):** Laphroaig's survivor maturation, Pōkeno's
  label outturn, and SMWS 10.258's cask number and maturation are independently
  supported. Those test cases now enumerate exact accepted operation sets that
  contain every required repair. Unlisted edits, extra findings, incomplete
  repairs, and updates to a merge source remain failures. The
  [M04 record](./experiments/M04-supported-audit-extras.md) reports the scoring
  correction.

For genuine field failures, keep evidence attached to the level it describes.
The Watchpost creation promoted a component age into the Bottle's stated age.
Other drafts omitted expected ABV, release year, or cask-strength values; an
expected value is not proof that the classifier had evidence for it. Test a focused
evidence review before the final answer, leaving weak facts unknown.

The creation judge currently reports `proposedBottle missing expected fields`
for many different mismatches. Reporting the mismatched field paths and values
would improve diagnosis without changing scoring or requiring another model.

## Luna experiment and acceptance criteria

1. Keep this baseline and the existing test case expectations fixed. Review any
   scoring corrections in a separate change with supporting evidence; record
   their effect separately.
2. Test only the marketed-trait compatibility change first, using Luna high
   against an unchanged Luna high run with the same extraction settings and
   reviewed source evidence. Repeat each focused case at least three times per
   version; alternate versions to reduce timing effects.
3. Include the Elijah Craig, Masterson's, and High Country failures; exact
   marketed-cask matches; genuine Midwinter Act/Scene releases; SMWS identifiers;
   and cases where harmless label details or missing catalog fields must not
   prevent a correct match. Add a realistic case with different concrete values
   to prove the rule generalizes. Keep that case out of prompt development.
4. Inspect every decision change. Require fewer unsupported existing matches,
   correct handling of ordinary lot codes, and no observed regressions on the
   positive comparison cases. A switch from a wrong match to `no_match` improves safety
   but does not count as a full pass where supported creation is required.
5. Once focused results support the change, run the complete Luna high suite
   once, then repeat new failures and material flips. Compare action/ID accuracy,
   field correctness, audit grounding, and run errors separately. Record
   token usage and tool calls so a gain does not hide an unbounded cost increase.

Entity reuse, audit recovery, and field completeness should be subsequent
experiments, one at a time. A production model switch needs a fresh comparison
with Terra after the classifier change; the historical three-case pass gap is
not enough to settle that decision.
